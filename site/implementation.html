Haskellで描画・音声・入力を実装する

01 / THE SAMPLE

Spaceを押すと何が起きるか

サンプルは窓から時刻と連番付きのイベントを読み取ります。reduceInputは、受け取ったイベントからキーやポインターの状態を更新し、変化の列を返します。updateに一件ずつ渡すと、Spaceの押下はマーカーの色を切り替え、鳴らす音の回数を1つ増やします。

events <- Platform.pollWindowEventsStamped window
let (input', changes) = Input.reduceInput input events
let (next, tones) = List.foldl' update (model, 0) (map snd changes)
unless (finished next) $ do
  replicateM_ tones playTone
  _ <- Graphics.renderFrame renderer (draw next)
  threadDelay 16000
  loop window renderer playTone input' next

updateの状態更新は、同じ入力から同じ値を返す純粋な処理です。その後、サンプルはHaskellで生成したPCMを再生し、renderFrameに新しい色の四角形を渡します。threadDelayはこのサンプルの待機です。ゲーム内の時計を進める間隔は、使うゲーム側が決めます。

02 / INPUT

フレームの間の押下と解放を残す

次の描画が16ms後だとします。その間に、3msでSpaceの押下、4msで解放を受け付けました。16ms時点ではキーが離れています。押下と解放の2件を残しておくと、ゲームはこの短い操作で色を変えられます。

Win32側の窓関数は受信箱に積む時点で時刻を記録し、連番を付けます。同じ時刻に記録した入力も連番順で扱えます。reduceInputの出力は、今の状態と順序付きの変化です。押した瞬間、押したまま、OSの自動リピートを区別し、フォーカスを失ったら残っている押下状態を取り消します。

reduceInput
  :: InputState
  -> [TimedWindowEvent]
  -> (InputState, [(HostStamp, InputChange)])

入力をゲーム内の更新に割り当てるときは、acceptEventsでイベントを蓄え、takeThroughで指定時刻までを取り出せます。締め切った更新に属する入力が遅れて届いたり、順序が逆転したりすると、エラーで呼び出し側へ知らせます。同じイベントを一度に渡した結果と、前半の状態を引き継いで分けて渡した結果を、テストで比べています。

Afterlightは60Hz、Red Duneは20Hzでゲームの状態を進めます。入力をどの更新に割り当てるか、遅れをどれだけ持ち越すかは、それぞれのゲームの時計に合わせて決めます。

この版のWin32窓関数は確定文字をイベントとして渡します。編集中の文字列と編集終了を表す値は、純粋な入力層の型にあります。

03 / SHADERS

Haskellの式でGPUの計算を書く

表面のUV座標を赤と緑に割り当てるフラグメントシェーダーです。MakeVec4で色を作り、青を0、不透明度を1にします。Haskellで組み立てるのはこの計算を表す値です。ライブラリが式をたどり、Vulkanへ渡すSPIR-Vの命令列を生成します。

uvColor :: FragmentShader
uvColor = FragmentShader $
  MakeVec4
    (Component X2 InterpolatedUV)
    (Component Y2 InterpolatedUV)
    0
    1

式の型はExpr local stage valueです。DataKindsで頂点とフラグメントをstageの型に表し、GADTで、各コンストラクターがどの段階で何成分の値を返すかを定めます。頂点を処理する時点で補間後のInterpolatedUVを使ったり、2成分を4成分として渡したりすると、GHCの型検査で止まります。

途中の値を表す形で、色が変わった反例

実装中、letExprの本体で受け取った式を調べると、CPUとGPUが別の色を選ぶ例が見つかりました。下のように、xがFloatLiteralなら赤成分を1にし、その他ならxを赤成分にする本体を書けます。CPUが数値リテラルを渡し、SPIR-V生成側が変数を渡す構成だと、同じ0.25を渡しても、CPUは1、GPUは0.25を選びます。

例はGameIO.Graphics.Shaderをimportし、パターン照合にGADTsを指定して試せます。

probe :: FragmentShader
probe = FragmentShader $
  letExpr 0.25 $ \x ->
    case x of
      FloatLiteral _ -> MakeVec4 1 0 0 1
      _              -> MakeVec4 x 0 0 1

現行版では両方で同じ非公開のBoundを渡します。内部にCPUの評価結果またはGPU命令のIDを持たせるので、本体からは同じ形に見えます。回帰試験は実際に分岐を書くシェーダーを使い、CPUの結果と描画した画素を照合します。

完結したFragmentShaderは、RankNTypesで任意のlocalに対して作れる式を要求します。letExprから受け取った途中の値は一つのlocalに結び付くので、別のシェーダーへ持ち出すと型が合いません。さらにRoleAnnotationsでExprのnominal roleを指定し、coerceでこの区別を外す操作も拒否します。

段階と値の型 完結した式の型 色と頂点出力の回帰検査 GHCが拒否する局所値の持ち出し

04 / GPU RESOURCES

画像を読む順序と、GPUの完了を管理する

湖面の反射を描くときは、先に反射用の画像Aへ景色を描き、湖面を描く処理がAを読みます。同じ画像に次の反射を書いたとき、計画は前の内容をA₁、新しい内容をA₂と区別します。この番号は、同じ記憶領域に書いたどの内容を読むかを表します。

planPassesは順に並んだ描画処理の読み書きを調べ、まだ書いていない画像を読む処理や、描画先を同じ処理で読む指定を拒否します。GPUで書いた内容を後の描画が読めるよう、同じキューにVulkanのバリアを入れ、実行段階、メモリ可視性、画像レイアウトを指定します。

たとえば前の描画がテクスチャを読んでいる間に、その同じ領域を新しい値で上書きすると、前の描画の入力が変わります。Game IOは資源を更新・解放する前に、必要な完了を待ちます。描画fenceと、提示に使ったセマフォを再利用できると判断するためのfenceは別々です。

最初の待機で完了が分からなければ、同じ仕事の完了を確認できる別の待機を試みます。それでも完了が不明な場合、CleanupGateが資源と窓を保持し、以後の描画・再利用も拒否します。待機に失敗した場合とVK_ERROR_DEVICE_LOSTを区別し、完了不明の資源を破棄しない経路を失敗注入で検査します。

画像を読む版と書く版の計画 画像の遷移 描画と提示の完了確認 待機失敗を注入する検査

05 / AUDIO

区切りが変わっても同じ位置で音を切り替える

48kHzのステレオ音声では、左と右のサンプルの組が1フレームで、480フレームは10ms分です。先頭を0と数え、127で最初の音を止めて次の音を始めるとします。480フレームを一度に作っても、127フレームを作ってから353フレームを続けても、切替位置は127です。

出力レート、初期状態、音源、命令の絶対位置、演算の順序をそろえます。検査では本番のミキサーを呼び、一括と分割で作ったFloat32のサンプル列と各音の最終状態を比較します。別に書いた有理数時刻の参照と照合すると、停止が1フレームずれた例も区別できます。

音源と出力のサンプルレートが異なると、読む位置に端数が生じます。ブロックをまたいで整数の位置と余りを持ち越し、次のブロックの先頭でもその続きから補間します。ストリームの先読みが足りなければ、位相を保って欠損を計上します。

MP3の復号表の一部はpuremp3やminimp3から移し、Vorbisは仕様とjfreymuth/vorbisを参照しました。出典とライセンスを公開しています。音声コーデックの出典

計算したサンプルを機器へ渡す

WASAPIが空きを知らせると、専用のOSスレッドがバッファを取得し、ミキサーが書き込んだサンプルを返します。withAudioはゲームと同じプロセスでこの処理を行います。withIsolatedAudioは別の実行ファイルを起動し、パイプで命令とPCMを送り、ゲームと機器への配送を別のGHCランタイムで実行します。

readAudioFrameで得るのは、まだ次のパケットに予約されていない最初のフレームです。位置を読んでから再生命令が届くまでに、そのフレームをミキサーが予約することがあります。その場合はAudioFrameAlreadyReservedを返すので、呼び出し側は先の位置を選び直せます。

約120MBの生存ヒープで100回GCを行った隔離試験では、Windowsの出力ミックスで10msのトーン区間を400個連続で取得し、捕捉の不連続と機器キューの空観測は0件でした。同一プロセスで行った試験では空観測が3件ありました。PCMの一致、機器に届く時刻、実際に聞こえる音はそれぞれ観測箇所が異なります。

06 / HASKELL FFI

GHCからWindowsへ値とアドレスを渡す

ウィンドウを作るCreateWindowExWは、HaskellのFFIで直接importします。Vulkanはvulkan-1.dllを開き、vkGetInstanceProcAddrなどで関数のアドレスを得ます。WASAPIのCOMメソッドは、オブジェクトの仮想関数表の所定の位置からアドレスを読みます。foreign import ccall "dynamic"は、取得した関数ポインターを指定した型で呼ぶ入口です。

ドライバーが読むバイト位置を合わせる

Vulkanの構造体で、先頭に4バイトのsType、続いて8バイトのポインターpNextを置くとします。Win64でpNextの位置は先頭から8バイトです。2つの間に4バイトの空きが入ります。Vulkan用の配置を計算するコードは、フィールドの幅と整列からこの位置を求めます。WASAPIのWAVEFORMATEXは18バイトの詰めた形式なので、別の固定オフセットを使います。

呼び返される間はアドレスを保持する

Windowsがメッセージを通知するときは、逆にHaskellを呼びます。FFIの"wrapper"で窓関数を関数ポインターにして登録します。窓関数の例外は受信箱に記録し、ゲームループで取り出します。終了時はウィンドウを破棄し、窓クラスの登録を解除してからポインターを解放します。

PCMの領域、位置の計算、出力バッファ

PCMはmallocForeignPtrArrayで連続した領域に確保します。GHCが動かさないpinned領域を使い、withForeignPtrでポインターの使用中は領域を生かします。前者はアドレス、後者は寿命のための指定です。

音源のフレーム位置と補間の余りは、内側のループのbang patternで厳密に評価します。これで、まだ計算していない式を反復ごとにためずに位置を進めます。ミキサーはWASAPIから借りた可変バッファへ各音を直接足し、最後に出力範囲へ収めます。

Afterlightでは、GPUにメッシュを送った後も、インデックス数を取り出す未評価の式がCPU側の頂点とインデックスの列を参照していました。登録時に個数を評価する変更を入れたビルドでは、送信後にGCをかけた時点の生存ヒープが約1,291MBから50.5MBになりました。1600×900、Full品質で5フレームを描いた非表示の起動診断です。累積割り当ては前後とも約7.36GBで、後のビルドにはシェーダーAPIの変更も含まれます。

OSスレッドと、例外が入る場所を決める

ウィンドウはrunInBoundThreadで同じOSスレッドに結び、操作時にもスレッドIDを照合します。音声は-threadedのGHCランタイムでforkOSWithUnmaskを使い、専用のOSスレッドでCOMの初期化、機器待ち、バッファの取得と返却を行います。機器待ちのFFIをsafeにすることで、その間も別のHaskellスレッドを動かせます。

bracketで取得と解放を組にします。WASAPIのパケットではmaskで取得・返却の境界を非同期例外から守り、サンプルを書く間は中断を許します。書き込みが例外で止まった場合は、無音のパケットとして機器へ返す経路があります。

この実装では、手書きのC・C++・Rustの中継コードを置かず、GHCが生成するFFIスタブとランタイム、WindowsのAPI、GPUドライバーを使います。

07 / IMAGES AND TEXT

ファイルと文字を描ける画素にする

画像は、ファイルの先頭を読んでPNG、JPEG、BMPを判別し、左上から並べたRGBA8の画素に変えます。PNGのDEFLATE展開、行フィルターの復元、JPEGの逆DCTと色変換をHaskellで実行します。JPEGの係数を展開する際はSTUArrayへ書き込み、runSTで更新を関数の内側に閉じます。呼ぶ側には画像かエラーが返ります。

日本語のラベルでは、フォントのcmapから文字のグリフ番号を探し、TrueTypeまたはOpenType CFF 1の曲線から輪郭を読みます。輪郭が各画素を覆う割合を求め、文字ごとのマスクを一枚のテクスチャに詰めます。描画、横幅、入力カーソルの計算は同じGlyphRunを使います。

設定画面のボタンをクリックしたとき、hitTestは座標に重なる有効な項目から最前面のIDを返します。stepUIに現在のフォーカスと操作を渡すと、次のフォーカスと決定された項目を返します。項目を削除したり無効にしたりすると、古いフォーカスは決定操作の対象から外れます。この更新は純粋関数なので、画面を開かずに同じ配置と操作で試せます。

文字配置は横一行を扱い、入力カーソルはUnicodeスカラーで数えます。画像は、PNGの標準色型とビット深度、Adam7、順次およびプログレッシブHuffman JPEG、非圧縮BMPと16・32-bitビットフィールドを対象にしています。ファイル形式ごとの制限は検査資料に記載しています。

画像の形式判別と寸法の検査 JPEGの係数処理 文字配置、幅、カーソル 当たり判定とフォーカスの更新 PNGとBMPの画素比較 JPEGの対応範囲と比較
